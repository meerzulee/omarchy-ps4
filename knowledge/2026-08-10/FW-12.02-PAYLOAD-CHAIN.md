# PS4 firmware 12.02 payload and Linux-loader chain

Snapshot: 2026-08-10; corrected for installed Vue release 2026-08-11

Console address in Orbis/GoldHEN mode: `192.168.50.215`

## Recommended path for the first Linux 6.18/XFCE boot

```text
Vue After Free 2.0 on firmware 12.02
  -> Lapse jailbreak and GoldHEN
  -> GoldHEN with PayLoader ready on TCP 9090
  -> PS4 Linux Loader v25, linux-1024mb.elf
  -> USB /bzImage + /initramfs.cpio.gz + /bootargs.txt + /vram.txt
  -> Arch/XFCE root filesystem on the USB ext4 partition
```

This path changes only the loader relative to the already prepared USB. It is
the smallest useful first-boot experiment.

The local PayLoader probe returned HTTP 200, `{ "status": "ready" }`, and the
`X-Powered-By: GoldHEN by SiSTRo` header from
`http://192.168.50.215:9090/status`. GoldHEN FTP on TCP 2121 was also reachable.
No Linux payload was sent during discovery.

## Installed jailbreak front-end: Vue After Free 2.0

- canonical repository: <https://github.com/Vuemony/vue-after-free>
- release: <https://github.com/Vuemony/vue-after-free/releases/tag/2.0>
- tag commit: `eb8d306b836e3bcbed84633d8e2e9da023e7dd8a`
- published: 2026-02-25
- installed variant: full Vue After Free 2.0, reported by the operator; **not**
  the `owendswang/vue-after-free-lite` fork

The full v2 UI supports `.bin` and `.elf` entries in its Payload Menu and uses
Lapse by default on firmware 12.02. Its own FAQ says that a Vue application
crash means the exploit failed and the console should be shut down before
trying again.

Hardware evidence on this console agrees with that distinction. Reopening Vue
after an already-active jailbreak produced a `SIGBUS` in `JavaScriptThread`.
The bundled `elfldr.elf` opened TCP 9021, but a later direct v25 ELF handoff in
that failed runtime returned `pt_mprotect`/`pt_msync` errors and
`elfldr_load failed`. This is evidence against reusing the post-crash elfldr
runtime; it is not evidence that PS4 Linux Loader v25 or Linux 6.18 is broken.

For the next clean attempt, run Vue 2.0 once to obtain GoldHEN, do not reopen
Vue, and deliver the pinned v25 artifact through GoldHEN PayLoader on TCP 9090.
This separates jailbreak stability from Linux-loader behavior.

The `ArabPixel/ps4-linux-payloads` URL now redirects to this canonical
repository. The older `ps4boot/ps4-linux-payloads` repository redirects to the
archived `ps4boot/ps4-linux-payloads-archive`. Do not treat them as three
independent current loaders.

v25 is one runtime-detecting payload family. It reads the exact Orbis firmware,
normalizes 12.02 to the 12.00 offset set, detects Aeolia/Belize/Belize2/Baikal
at runtime, and embeds a kexec blob for every supported canonical firmware.
Separate Baikal or Pro payloads are no longer required.

The release contains BIN and ELF variants for 32, 64, 128, 256, 512, 1024,
2048, 3072 and 4096MB VRAM. Prefer the ELF through GoldHEN PayLoader. Use the
1024MB build for the initial XFCE desktop test.

### File discovery and precedence

The current source checks each filename independently in this exact order:

1. `/mnt/usb0/`
2. `/mnt/usb1/`
3. `/data/linux/boot/`
4. `/user/system/boot/`

`bzImage` and `initramfs.cpio.gz` are mandatory. `bootargs.txt` and `vram.txt`
are optional. A partially populated USB can therefore mix files with internal
fallbacks; always keep all four files together and checksum them before boot.

`vram.txt` is expressed in MB in v25: use `1024`, not `1`, for 1GB. An invalid
value falls back to the default compiled into the selected payload, so loading
`linux-1024mb.elf` with the currently prepared `vram.txt=1` still resolves to
1024MB. Change the USB file to `1024` before calling the setup final.

### Source-audit findings

- The README says boot files are automatically copied from USB to
  `/data/linux/boot`, but no copy/write implementation exists in the v25 source
  tree. The loader only reads from the four locations above. Do not depend on
  automatic installation.
- The README says Orbis time is appended to the kernel command line, but no
  `time=` or RTC-command-line implementation exists in the v25 source. Treat
  that text as stale until code appears.
- The repository has no root license file or GitHub-detected license. Keep the
  downloaded binaries local and link to upstream rather than redistributing
  them in a public package until the maintainer clarifies licensing.

## First experiment

1. Start a bounded UART session.
2. Confirm PayLoader still reports `ready` on port 9090.
3. Attach the prepared Kingston Linux USB to the PS4.
4. Send v25 `elf/linux-1024mb.elf` through GoldHEN PayLoader without reopening
   Vue.
5. Stop the UART session only after XFCE appears or the boot reaches a stable
   failure.
6. Record which source path the loader selected and preserve the generated
   Markdown context plus exact raw UART slice.

Pass status remains **untested** until the real console completes the boot.
