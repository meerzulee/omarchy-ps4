# Omarchy PS4 v0.31 — Baikal beta

Status: public development beta. This is a meaningful release bundle for the
accepted Baikal B1 boot path, not a production release and not a jailbreak.
It is published unsigned; release signing and repeated hardware acceptance
remain open.

- system release: `omarchy-ps4-4.0.0-baikal-b1-beta1`
- manager version: `0.31`

- display policy: `1920x1080@60`

profile, user interface or USB release identity. That name remains only in the

## What the bundle does

1. The FPKG verifies and installs the matching kernel, initramfs, boot
   arguments and VRAM setting in the application's internal storage.
2. Launch hands the verified boot set to the local Linux loader.
3. The initramfs waits for and validates the external ext4 root labelled
   `OMARCHY-PS4`.
4. The USB provides the complete Omarchy userspace and matching kernel modules.
5. On a fresh USB, deferred owner setup creates the user's account and password
   before the desktop is used.

The supported path does not use the PS4 internal SATA disk as the Linux root
filesystem and does not format it.

### Owner-form and autologin follow-up

The prepared hardware-test USB currently carries
`omarchy-ps4-provisioning 4.0.0-17`. It fixed the first-owner screen where the
Omarchy headings appeared but keyboard/timezone choices and typed input were
invisible: Gum returns values on stdout but renders interactive widgets on
stderr, while the service deliberately journals ordinary stderr. The fix sends
only Gum's renderer to `/dev/tty1`, keeps technical errors in the journal and
adds centered, high-contrast focus styling.

The photographed v17 run then exposed two narrower presentation defects: the
live timezone filter left stale frames on the Linux VT, and the final review
card used a three-value margin that placed it at the left edge. The local v18
candidate replaces the filter with clean region/location lists, centers the
review by measured terminal width, and renders a fixed green Yes plus gray No.

Later privileged LightDM evidence identified the greeter fallback's actual
cause: `sessions-directory` had been appended to a file whose active section
was `[Seat:*]`, but LightDM accepts that option only under `[LightDM]`. It
therefore never searched `/usr/local/share/wayland-sessions`, could not resolve
the `omarchy` session, and opened the greeter. The live system and current
rootfs source now put the session path in the global section. The v18 PAM
candidate predates that diagnosis and is not the evidence for the fix; its
extra PAM policy must be reviewed before the next composed image. Normal
password login remains the fallback, and persistent autologin is not accepted
until a bounded reboot passes.

The same live investigation found that Docker's `/.dockerenv` marker had been
exported into the USB root. That made `systemd-detect-virt` report `docker` on
the PS4, so `systemd-timesyncd` did not start on a machine with no usable RTC.
The current rootfs exporter excludes the marker. Network-time persistence also
requires a bounded reboot pass.

The frozen beta1 rootfs archive above still contains provisioning v4.0.0-16
and predates both rootfs-source fixes. Do not distribute that archive as the
fixed image. Rebuild the package snapshot and rootfs after the owner form,
session discovery, autologin and network-time path pass hardware acceptance.

## Publication gate

Keep this release private. Redistribution rights for the embedded loader and
selected wallpaper assets remain unresolved. The release manifest deliberately
does not publish private console firmware information. A public binary release
requires replacing or clearing those inputs and completing repeated hardware
acceptance.
